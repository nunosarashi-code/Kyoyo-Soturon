# Fish Folk Taxonomy Analyzer（FFTA）

魚類の地方名、民俗分類単位、魚種、利用、出典を調査文脈ごとに整理する、卒業論文研究向けのローカルアプリです。Phase 1の登録・検索・分類対応図に、2都道府県の共通魚種について地方名記録数を比較する画面と、全体CSVから別のSQLiteを作成するコマンドを加えました。

復旧用ZIPの11月8日全体版から地方名79件、出典7件、調査文脈4件、利用記録2件を再生成できます。確認状況は元データに沿って保持し、北海道・道北と福島県列の資料に共通する14標準和名について、添付の比較結果と一致することを検証しました。 [復旧レポート](./RECOVERY_REPORT.md)

## セットアップと起動

展開したプロジェクトフォルダーで実行します。Python 3.11 以上と、その Python に組み込まれた SQLite 3.37 以上が必要です。

**macOS / Linux**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

**Windows（PowerShell）**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

ブラウザーで [http://127.0.0.1:8501](http://127.0.0.1:8501) を開きます。終了はターミナルで Ctrl+C です。インストール後はインターネット接続やAPIキーなしで操作できます。依存関係は pandas、Streamlit、Plotly、pytest です。

### SQLite の保存先

- 初回の「研究データ」は空の `data/ffta.sqlite3` を作成します。既存のFFTAデータベースは次回以降も利用されます。
- 「架空デモ」は `data/ffta_demo.sqlite3` に同梱のCSVを初回だけ取り込みます。画面からは閲覧専用です。デモの「確認済み」は架空の出典を使った表示例です。
- 起動前に環境変数 `FFTA_DATA_DIR` を設定すると、両ファイルを指定ディレクトリに保存できます。バックアップはアプリを停止してから研究用SQLiteファイルをコピーします。
- DDL は `ffta/schema.sql`、バージョン確認と初期化は `ffta/storage.py` にあります。アプリの接続では外部キーを有効にしています。

## 操作方法

1. サイドバーの「架空デモ」を選ぶと、検索と分類対応を試せます。分類対応で2つの文脈を選ぶと、同じ架空魚種の分かれ方を文脈ごとに確認できます。
2. 研究資料を追加するときは「研究データ」→「データ管理」→「テンプレート」を開きます。`csv/templates/` のCSVも利用できます。「登録・編集・削除」ではテーブルを選んで1件ずつ操作できます。IDは登録時に決め、参照されているレコードの削除は参照を整理した後に行います。
3. 一括登録は「CSVインポート」で行います。参照し合うファイルをまとめて選び、「検証する」を押します。エラーの行・列と内容を確認し、CSVを修正して再検証します。検証が通ったら確認欄を選び「取り込む」を押します。取り込み時にも再検証し、エラーがあれば全ファイルの登録を取り消します。
4. 「検索」で標準和名・学名・地方名または読み方・属/科/目・地域・用途を指定します。入力項目を組み合わせ、複数選択の地域と用途は各項目の中でOR条件になります。用途で絞ると「利用あり」の記録がある対象を表示します。「出典」タブで、結果の出典IDに対応する書誌情報と引用箇所を見られます。
5. 「分類対応」では調査文脈ごとに、魚種から民俗分類単位への線を表示します。合流は複数種に対応する単位、分岐は同じ魚種に対応する複数の単位を示します。表では出典ごとの確実性を確認できます。文脈の比較には時期、利用者集団、調査・記録方法、調査範囲の確認が必要です。
6. 「地域間比較」で2都道府県と、それぞれの調査文脈を選びます。北海道と福島県が登録済みなら最初に選ばれ、地方名レコードのある文脈が優先されます。両方に地方名記録がある共通魚種の比較表・棒グラフを表示できます。「調査文脈・出典」で時期、方法、各文脈の件数、使用した資料を確認できます。表をCSVに出力でき、根拠と抽出条件を含むZIPも保存できます。

検索と分類対応には、CSVで結果・出典をまとめたZIP出力があります。各CSVにデータ区分が入り、`manifest.json` に抽出条件、実行日時（UTC）、ツールとスキーマの版、CSVごとの行数とSHA-256が入ります。分類対応図はPlotlyを同梱した単体のHTMLで保存できます。図には文脈IDとデータ区分が入り、線にマウスを重ねると対応IDと出典IDを確認できます。

## CSVの入力契約

テンプレートのファイル名と列名を使い、UTF-8（BOMの有無は任意）で保存します。列順は任意です。空欄は欠損として保存します。日付は `YYYY-MM-DD`、年は1〜9999の整数、緯度経度は十進度です。出典のDOI/URL欄には DOI（`10.…/…`）または HTTP/HTTPS のURLを入力します。カンマや引用符を含む原文はCSVの引用規則に従って入力すると、改行も保存されます。表計算ソフトではIDを文字列として扱うと先頭のゼロを保持できます。

| ファイル | 1行の意味 | 主な必須値と参照先 |
| --- | --- | --- |
| `sources.csv` | 文献・聞き取り等の特定箇所 | `source_id` と `verification_status`。確認済みは表題と、著者・出版情報・DOI/URLのいずれかが必要 |
| `species.csv` | 生物学的な魚種の登録 | `species_id`、標準和名か学名の一方以上、`name_status`。確認済みは両方の名前と確認済み出典が必要 |
| `regions.csv` | 調査地 | `region_id`、都道府県、市町村・集落 |
| `contexts.csv` | 地域・時代・利用者集団を含む調査の文脈 | `context_id`、`region_id`、文脈名。時期、集団、記録方法、範囲は判明分を記録 |
| `folk_units.csv` | ある文脈で区別された、または候補になった民俗分類単位 | `unit_id`、`context_id`、`unit_status`。上位単位は同じ文脈で指定。区別の記載を確認済みにする場合は確認済み出典が必要 |
| `local_names.csv` | ある文脈における、資料に出現した地方名 | `local_name_id`、表記、`context_id`、`form_type`。呼称と別名には同じ文脈の単位IDを指定 |
| `unit_species.csv` | 分類単位と魚種の1つの対応についての出典別記録 | `mapping_id`、`unit_id`、`species_id`、`certainty` |
| `name_species.csv` | 魚種を指すことが資料に直接記載された地方名と、その証拠 | `name_mapping_id`、`local_name_id`、`species_id`、`certainty`。所属単位が分からない語にも利用できる |
| `uses.csv` | 文脈と対象を限定した利用の記載 | `use_id`、`context_id`、`use_status`、魚種IDか単位IDの一方。利用ありは目的が1つ以上必要。利用なしの明記には出典IDが必要 |

地域、調査文脈、魚種、分類単位、地方名、対応、利用には、それぞれ `source_id` を付けられます。文献の異なるページや別々の引用は、必要に応じて出典IDを分けます。表の参照列にIDを入力する場合は、登録済みか同じ一括取り込み内に含めます。CSVは追加専用で、既存行は「編集」で修正します。結果出力のCSVは抽出条件と合わせて保管するための形式です。再入力には配布テンプレートを使います。

### 入力コード

| 列 | コード |
| --- | --- |
| `verification_status` | `verified` 確認済み、`unverified` 未確認、`unknown` 出典不明 |
| `name_status` | `verified` 確認済み、`unverified` 未確認 |
| `unit_status` | `documented` 区別の記載を確認済み、`provisional` 分類単位が未確定 |
| `form_type` | `label` 分類単位の呼称、`synonym` 同じ分類単位の別名、`unresolved` 単位への所属が未確認（単位IDは空欄） |
| `certainty` | `confirmed` 対応の根拠を確認済み（確認済み出典が必要）、`probable` 推定、`uncertain` 不明 |
| `use_status` | `used` 利用あり、`not_used` 利用なしの記載あり、`unknown` 利用について記録なし |
| `purposes` | `food` 食用、`craft` 工芸、`tool` 道具、`medicine` 薬用、`ritual` 儀礼、`commercial` 商業、`other` その他。複数は `food\|commercial` のように半角の縦棒で区切る |

利用記録が見当たらない対象は行なしで保持できます。資料を調べて利用記載が見当たらなかった経緯を残したい場合は `unknown` を登録します。`not_used` の意味は記録した対象・用途・調査文脈の範囲内です。用途が空欄なら、範囲は原文と備考で確認します。利用部位、方法、頻度、文化的重要性の記述は、資料の表現に沿って保持します。

## 更新済み全体CSVから検証用DBを作る

`FFTA_recovery_bundle_2026-11-23.zip` から再現する場合は、元のZIPを指定して新しい出力ディレクトリを作成します。

```bash
python -m ffta.recover_bundle path/to/FFTA_recovery_bundle_2026-11-23.zip --output-dir data/recovered-2026-11-24
FFTA_DATA_DIR=data/recovered-2026-11-24/research python -m streamlit run app.py
```

PowerShellでは起動前に `$env:FFTA_DATA_DIR = 'data/recovered-2026-11-24/research'` を設定します。

復旧処理は11月8日全体版を1回取り込み、初期版と増分のID集合・増分の列値を照合します。既存の出力先は受け付けません。成果物は以下のとおりです。

| フォルダー | 内容 |
| --- | --- |
| `research/` | 新しい研究用 `ffta.sqlite3`。架空デモは別ファイル `ffta_demo.sqlite3` に初期化されます。 |
| `normalized/` | 再生成用のPhase 1形式CSV9種類。 |
| `comparison/` | 14標準和名の比較CSV、根拠付きZIP、オフラインで開く比較HTML。 |
| `audit/` | 入力一覧とSHA-256、検証結果、行監査、旧ID対応表、保留資料。 |

地方名の単位所属は未確認のまま保存しています。名称と標準和名の資料上の対応は行監査と照合して登録し、旧仮置き単位IDを `legacy_name_crosswalk.csv` で追跡できます。旧版にしかない備考等は `legacy_fields.csv` に保持し、群レベルの用例など保留資料は監査フォルダーに収録します。研究用DB、実データCSV、出力グラフはローカルに保管してください。

### 正規化済みのCSVから新規作成する場合

更新済み全体データをPhase 1のCSV契約に合わせ、9種類を1つのフォルダーに揃えます。出典IDや調査文脈IDを照合し、分類単位が仮置きなら `provisional` で保持します。初期データや差分CSVは別フォルダーに保管します。旧版の項目が取り込み先と一致するかは、旧版READMEとデータを読んで確定する必要があります。

```bash
python -m ffta.rebuild path/to/normalized-full-csv --database path/to/recovery-check/ffta.sqlite3
```

検証に成功した場合は新しいSQLiteを保存し、テーブル件数と入力CSVのSHA-256を表示します。すでに存在するDBや関連ファイルのある保存先は受け付けません。参照エラー、重複、範囲外の値などで検証に失敗した場合、指定先へのDB作成は取り消されます。

検証用ディレクトリを使って起動します。以下はmacOS/Linuxの例です。WindowsのPowerShellでは起動前に `$env:FFTA_DATA_DIR = 'path/to/recovery-check'` を設定します。

```bash
FFTA_DATA_DIR=path/to/recovery-check python -m streamlit run app.py
```

## 地域間比較の集計単位

- 選択した都道府県・調査文脈ごとに、魚種IDと地方名IDの組を1件と数えます。同じ地方名への複数の対応根拠を集約し、異なる地方名IDは表記が同じでも別の記録として扱います。
- 地方名と魚種の直接の記載があるときはその対応を使用し、直接の記載を欠く地方名は登録された民俗分類単位の対応を参照します。1つの地方名が複数の魚種に対応するときは各魚種に含めます。
- 初期表示は記載されたすべての対応を対象にします。「確認済みの記録に限定する」を選ぶと、和名・学名の対応、地方名の出典、魚種対応とその出典を確認済みとする記録が対象です。民俗分類単位を経由する場合は、単位の区別の記載も確認済みである必要があります。地方名ID、対応ID、出典ID、確認状況は根拠表で追跡できます。
- 記録数は収録範囲に依存します。比較結果を解釈する際は文脈の調査方法、時期、範囲、記録密度を参照してください。

## 設計上の仮定と既知の範囲

- 調査文脈は1つの地域に属します。同じ集落でも時代、利用者集団、方法、範囲が違う場合は文脈IDを分けられます。座標は片方だけ判明している場合も保存できます。
- 分類単位の同一性は、入力者が出典を照合して決めます。複数の地方名を同じ単位に関連付けられ、同じ表記を異なる文脈・単位にも登録できます。階層は同じ文脈の上位単位への参照で表します。
- 分類単位と魚種は多対多です。対応1組につき、異なる出典の記録を併存させます。同じ出典の同じ対応、および同じ出典・文脈・単位・読み方の同じ地方名の登録は重複として検出します。全テーブルでIDの重複を検出し、確認済みの学名にも重複検査を行います。`DEMO_` で始まるIDは架空デモ専用です。
- 地方名の検索で魚種の直接記載があれば、その記録を語の指示対象として検索します。直接記載がなければ関連付けた分類単位を通じて検索します。上位・下位の階層からの魚種対応の継承や、所属未確認の語からの単位の生成は行いません。図の線は `unit_species.csv` の記録に基づきます。
- 同じ文脈・同じ魚種と単位の組は、出典が複数でも図では1本です。対応の根拠・分類単位の区別・和名と学名の対応をすべて確認済みとした記録は青緑で、確認済みの記録と暫定の記録が混在する場合は橙、暫定のみの場合は灰色で表示します。
- 用途による検索では同じ文脈の魚種または単位に結び付いた記録が該当します。結果の「利用」タブで、原記録の対象が魚種だったか、民俗分類単位だったかを確認できます。
- 確認状況は利用者の読解・照合結果を記録します。DOI/URLは書式を検証します。実在性・分類学的妥当性・出典の内容の確認は入力者が行います。
- 現版は小〜中規模の手入力・CSV中心の研究データを、手元の1台で扱うことを想定します。検索・作図では読み取り時点のデータをメモリに保持します。編集・削除の履歴を残したい場合は、研究用SQLiteやエクスポートを版ごとに保管します。

## 実データを集める前のチェックリスト

- [ ] **研究対象と比較範囲**　地域、時期・季節、対象集団、対象の魚類群と選定基準を定めた。分類粒度の分母候補になる調査対象種の一覧を、地方名が得られた魚種だけに限定せず記録できる。
- [ ] **調査方法**　聞き取り、文献、観察などの収集方法、質問文、調査努力量、資料の網羅性、分類階層を記録できる。比較の対象に含める条件を先に定めた。
- [ ] **分類学的な照合**　標準和名と学名、属・科・目、採用した分類体系の版、照合日、参照元を記録できる。同定が難しい対象や複数候補は未確認・推定として保持できる。
- [ ] **地方名の文脈**　表記、読み、誰がどこでいつ使ったか、サイズ・成長段階、形態・生息環境・行動などの区別根拠を記録できる。同義、同音異義、上位下位、資料間の不一致を照合した。
- [ ] **利用情報**　記載の対象と文脈、目的、部位、方法、頻度の期間・単位・観測範囲、重要性の原文、明示的な非利用の根拠を取得できる。記載が得られなかった場合を区別できる。
- [ ] **仮説の検証計画**　H1/H2で使う重要性の証拠（例として頻度・取引・儀礼など）と、H3で比較する区別基準の記録方法を事前に定めた。異質な重要性の記述は根拠とともに保持し、集計単位と欠損の扱いを決めた。
- [ ] **出典付与**　著者、年、題名、掲載誌・出版社、DOI/URL、ページ、原文、抽出日、確認状態をできるだけ記録した。同じ出典IDから該当箇所に戻れる。
- [ ] **利用許諾と研究倫理**　引用・転載や配布の許諾、資料の利用条件、聞き取りの研究倫理、匿名化、公開範囲を確認した。
- [ ] **再現性**　取り込み用CSV、抽出条件、使用した出典、研究用SQLiteの版を保管し、架空デモを研究資料から除外できる。

福島県の海産動物方言集、北海道立総合研究機構の魚類地方名一覧、各地の方言集・民俗資料、学術論文、GBIF等は今後の調査候補です。同梱CSVは動作確認用の架空記録です。

## テストと次のフェーズ

```bash
.venv/bin/python -m pytest -q
```

Windowsでは `.\.venv\Scripts\python.exe -m pytest -q` を使います。SQLiteの参照整合性、CSVの検証と一括登録・ロールバック、研究とデモの分離、検索、別名の扱い、図と出典付き出力、Streamlitの主要操作をテストします。追加の回帰テストでは、新規DBの作成と既存ファイルの保護、重複の拒否、仮置き単位の維持、共通魚種の条件、地域・文脈ごとの集計、出典付きエクスポートを検証します。

添付の実データで復旧回帰テストを実行するには、`FFTA_RECOVERY_TEST_BUNDLE` にZIPを指定します。未指定の場合、実データを必要とするケースをスキップします。

```bash
FFTA_RECOVERY_TEST_BUNDLE=path/to/FFTA_recovery_bundle_2026-11-23.zip python -m pytest -q -ra
```

`FFTA_PHASE2_TEST_DB` に復旧版の元DBを指定すると、Phase 2の監査反映テストも実行できます。テスト用の一時ファイルで、不確実性の維持と文脈の不整合の検出を確認します。

```bash
FFTA_PHASE2_TEST_DB=path/to/recovered/research/ffta.sqlite3 python -m pytest -q -ra tests/test_phase2_audit.py
```
